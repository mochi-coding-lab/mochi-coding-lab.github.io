Mochi Chapter 1: how the app fits together

Ten beginner Python tasks connect a lesson, a real Python run, visible farm changes, feedback, and saved progress. The chapter runs in the browser; the separate world map reads Chapter 1 progress to show island completion.

One learner action, through the code

Example: a learner runs farm.prepare_bed(length, breadth). The lesson validates the returned result, updates the farm scene and feedback, and saves the resulting chapter state. Guest progress is stored under mochi.farm.chapter1.v2 in local browser storage.

Reference route: three stops in the source

  1. public/farm-chapter-content.js — window.FARM_CHAPTER_STEPS. Each task’s stable ID, story, explanation, prompt, example, hint and reward are authored here. The current task IDs also define the 10-task map counter.
  2. public/farm-chapter.js — render(), execute(), finishActivity(). This connects task content to the lesson/editor, runs code, checks results, shows feedback and updates saved progress/rewards. restoredState() handles saves from the older task plan.
  3. public/farm-python-worker.js — self.onmessage. The browser Worker loads Python and executes submitted code separately from the page, returning output or an error for the lesson to display.

To change this, start here

  • Lesson wording, stable task ID, example or XP: edit public/farm-chapter-content.js; keep IDs stable when possible because saved progress refers to them.
  • How code success, feedback or rewards behave: inspect public/farm-chapter.js, especially execute() and finishActivity().
  • How the map counts the current chapter: inspect public/world-map-home.js, chapterIDs and local(). The retained IDs there should match the task content.

A practice to reuse

When the chapter changed from 12 activities to 10 tasks, the homepage counter still reflected the retired plan. The repair aligned the map’s stable task IDs with FARM_CHAPTER_STEPS and checked the public-map regressions. In another project, keep a visible progress counter tied to the same canonical item IDs as the content, then check both current and older saved progress after shortening a sequence.

Open and run the project

Open the published Chapter 1 demo in a browser. In the source repository, the app files are in public/; serve that folder from a local HTTP server to run the source preview (the lesson uses browser workers, so open it over HTTP rather than as a file). This map itself is self-contained and works offline.

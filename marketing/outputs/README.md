# Marketing Outputs

Save completed local content packages, research notes and feedback syntheses here. This folder is not a publishing service or a private-data vault.

## Naming and review

Use `YYYY-MM-DD-short-topic.md`; add a version suffix when preserving a meaningful revision. Keep related language variants in one package unless separate files serve the request. Link the output from CONTENT_BACKLOG.md and relevant memory/experiment entries.

Start each deliverable with its date, intended audience, language/channel assumptions, evidence sources, factual status and publication status (draft / approved / published). Publication requires approval; only record published when there is evidence. Explain whether visuals are actual prototype footage, concept mockups or assets still to produce.

For requested posts/videos include hook, full script/body, shot or frame list, exact on-screen text, caption, CTA/question and learning goal. Scripts and shot lists are production-ready instructions, not a claim that a video has been rendered. Other tasks should contain the complete requested deliverable rather than general advice.

## Privacy and boundaries

Exclude private raw feedback, identities, credentials and identifying screenshots. Never invent quotes, testimonials or results. Keep BubblyCue material out. Do not draft the user's final hackathon submission or peer feedback here; preserve the learner-authorship rule in the existing 6-ship skill.
